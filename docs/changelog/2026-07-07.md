## Connector Directory + click-to-connect OAuth
- **What:** Browsable connector catalog in the Connectors tab (Notion, Linear, Sentry, Atlassian, Asana, Canva, Figma, Stripe, Hugging Face, Context7, DeepWiki, GitHub, Filesystem). One click connects: `none` entries connect instantly, `token` entries take one paste, `oauth` entries run a full OAuth 2.1 flow — RFC 9728 discovery, RFC 7591 dynamic client registration, PKCE, loopback callback on 127.0.0.1, token exchange — implemented in the sidecar (`oauth.ts`). Token sets are stored in the OS keychain via a new privileged `store_secret` core message and auto-refreshed when expired at MCP client build time. New protocol messages: `oauth_start`/`oauth_result` (ui), `store_secret`/`secret_stored` (core).
- **Why:** user request — connect services by clicking a card (like Claude's Directory) instead of pasting MCP URLs; browser redirect for services that need sign-in.
- **Verification:** end-to-end pass against the real sidecar with a fake authorization server + fake core (`sidecar/spikes/oauth-e2e.ts`): discovery → registration → PKCE authorize → redirect → token exchange → keychain write → `oauth_result ok`.
- **Files:** packages/protocol/src/index.ts, sidecar/src/{oauth.ts,index.ts,core-bridge.ts,mcp/manager.ts}, src-tauri/src/core_client.rs, frontend/src/lib/{connector-catalog.ts,agent-socket.ts}, frontend/src/windows/connectors.tsx, sidecar/spikes/oauth-e2e.ts.
- **Security note:** directory HTTP connectors are auto-enabled after connect (nothing runs locally); stdio entries (filesystem) still stay disabled until the command is reviewed, per PRD §9.4.

## Self-healing Ollama model setup (Hermes-inspired)
- **What:** studied NousResearch/hermes-agent's "no plumbing" onboarding at the user's request. Ollama mode no longer dead-ends on "model not found": the sidecar preflights the local server at model-build time and resolves the model itself — exact match, then same-family tag (qwen3:8b → qwen3:1.7b), then the best installed tool-calling model; only server-down / zero-models surface as errors, with plain-language instructions. Settings shows live Ollama status (running + model count), a dropdown of installed models instead of a free-text field, and a one-click in-app download of the recommended model with streaming NDJSON progress.
- **Verification:** `sidecar/spikes/ollama-resolver-test.ts` live against local Ollama — configured qwen3:8b resolved to installed qwen3:1.7b; empty/exact/family/tool-capable pick cases all pass.
- **Files:** sidecar/src/agent/{ollama.ts,provider.ts}, frontend/src/lib/ollama.ts, frontend/src/windows/settings.tsx, sidecar/spikes/ollama-resolver-test.ts.
