# 2026-07-11

## Google Workspace connectors (shared OAuth sign-in)
- **What:** Gmail, Google Drive, Google Calendar, and Google Chat in the connector directory, backed by Google's official hosted MCP servers. New "OAuth preset" flow for providers without RFC 7591 dynamic registration: the catalog entry carries fixed endpoints + scopes, the user pastes a one-time OAuth client (Desktop-app type from Google Cloud Console), and the sidecar runs PKCE against Google directly (`access_type=offline`, `prompt=consent`). All four Google connectors share one keychain token set (`google_oauth`) — the first connect pays a single consent for the scope union; siblings just toggle on. Reconnect on OAuth-backed rows reuses the stored client credentials; `remove_server` keeps shared secrets until the last referrer is gone.
- **Why:** user wants many real MCP connectors manageable from the app, Google being the priority; Google's authorization server cannot auto-register clients so the existing DCR flow could not reach it.
- **Files:** packages/protocol/src/index.ts (+ index.test.ts), sidecar/src/{oauth.ts,index.ts}, frontend/src/lib/{connector-catalog.ts,agent-socket.ts}, frontend/src/windows/connectors.tsx, src-tauri/src/commands/connectors.rs, docs/context/api.md.
- **Breaking:** none (protocol change is backward compatible).

## Onboarding permissions flow
- **What:** the wizard's permissions step now covers every OS permission Vox uses — microphone (real TCC state via AVFoundation, prompt fired by a brief capture), Accessibility (AX consent prompt fired directly), and notifications (tauri-plugin-notification) — each row states why the permission is needed and when it is used, refreshes live every 2s, and is skippable. A shared `PermissionList` also powers a new Settings → Permissions section, and the post-onboarding banner catches denied mic / missing Accessibility with one-click fixes. Agent flows raise system notifications for approval requests and questions only while the app is unfocused.
- **Why:** production onboarding must explain and request all required permissions up front (user goal); previously mic state was faked by device presence and notifications did not exist.
- **Files:** src-tauri/src/commands/permissions.rs, src-tauri/src/lib.rs, src-tauri/Cargo.toml, src-tauri/capabilities/default.json, frontend/src/lib/{permissions.ts,notify.ts}, frontend/src/components/vox/{onboarding.tsx,permission-list.tsx,permissions-banner.tsx}, frontend/src/lib/agent-socket.ts.
- **Breaking:** none.
